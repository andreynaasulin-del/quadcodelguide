# Совмещение музыкального дропа с пиком движения (замеренный метод)

Кейс: `assets/video/urban-fashion-fisheye-v3.mp4` = видеопоток v2 + пересобранный звук.

## 1. Где пик движения — измерять, а не смотреть
```
ffmpeg -i clip.mp4 -an -vf "scdet=t=0:s=1,metadata=print:file=out.txt" -f null -
```
`scdet` печатает `lavfi.scd.score` для каждого кадра. Одиночный спайк 20–30 = склейка,
а настоящий «движ» — это плотная серия средних значений после ката.

Профиль v2 (361 кадр, 24 fps), средний score по секундам:
- 0–4.6s — 1.7…2.8 (плотная нарезка, дневной блок)
- 5.0–9.2s — 0.3…0.45 (самая мёртвая зона, макро-вставки на статике)
- **9.2–10.1s — 2.88, максимум клипа**: кат 19.9 на 9.208, дальше 7.66 / 5.08 / 4.11 / 3.78 / 6.69
- 11.9 и 13.0 — одиночные каты 30.6 и 22.9 без движения после них
- 13.5–15.0s — 0.03, картинка практически заморожена

Вывод: климакс — 9.208s (кадр 221), а не финал. По одним катам этого не увидеть:
самый высокий score всего клипа (30.6 на 11.9s) — это статичная склейка.

## 2. Где дроп в треке — по низу спектра
```
ffmpeg -i track.mp3 -af "lowpass=f=160,asetnsamples=44100,astats=metadata=1:reset=1,\
ametadata=print:key=lavfi.astats.Overall.RMS_level:file=rms.txt" -f null -
```
Дроп = вход кика и баса, поэтому мерить надо полосу до 160 Гц, а не общую громкость:
на общем RMS вокал и синты в брейке маскируют провал.

`.temp/upload/refhouse.mp3` (232s), низ по секундам: интро 0–14 = −21 dB;
дроп #1 с 15s = −9; брейк 30–59 = −13…−25; средняя секция 60–71 = −13;
**провал 72–74 = −29/−34/−31; главный дроп с 75s = −9**; далее 89/104/119 — однобарные
дырки. Уточнение окном 50 мс: онсет = 75.20s (за 50 мс −27.1 → −12.97 dB).

ГРАБЛИ: в прошлой итерации кусок брался с 62s «на глаз по вайбу» — это была средняя
секция на 4 dB тише реального дропа. Отсюда и жалоба, что движ приходит в конце.

## 3. Сборка
Старт музыки = онсет дропа − время пика = 75.20 − 9.208 = **65.992s**, длина 15.093s.
Бонус от структуры трека: провал 72–75 попал ровно в мёртвую зону видео 6.2–9.2s.
```
ffmpeg -ss 65.992 -t 15.093 -i ref.mp3 -af "afade=t=in:st=0:d=0.10,afade=t=out:st=14.593:d=0.50" \
  -c:a pcm_s16le bed.wav
ffmpeg -i v2.mp4 -i bed.wav -map 0:v:0 -map 1:a:0 -c:v copy -c:a aac -b:a 224k -shortest v3.mp4
```
- Промежуточный файл — **WAV, не MP3**: mp3-энкодер добавляет ~26 мс задержки и
  подгоняет длину под фрейм, из-за чего склейка уезжает почти на кадр.
- `-c:v copy` → видеопоток бит-в-бит. Проверка: `-f md5` по `0:v` у обоих файлов
  дал одинаковый `16ec43379a9d1fbbec3964027ee473a1`.
- Родной звук Seedance выброшен целиком, а не подмешан тише: два трека в разных
  темпах и тональностях дают кашу даже на −18 dB.

## 4. Приёмка
Низ v3 по секундам: 0–5s = −13.6…−14.4 → 6–8s = −28.5/−34.8/−31.8 → с 9.2s = −9.0…−10.4.
Контраст брейк → дроп = **22.8 dB**. Кик по окну 10 мс встал на 9.203s, то есть на 5 мс
(0.12 кадра) раньше ката — так и надо, звук чуть впереди картинки читается как «в точку».

## 5. Замеченный лимит Seedance
AUDIO-INPUT ≤ 15s, причём 15.02s уже отбивается ошибкой «maximum allowed is 15s», и
звук нельзя передать без визуального референса: «At least one reference image or video
is required when audio is provided».
