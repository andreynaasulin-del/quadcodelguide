JERRY/01 — Restyle a physics-driven testimonial rig into the Quadcode system

Take a third-party Three.js testimonial widget (rope-physics puller, canvas-textured cards) and rebuild its whole visual language — CSS tokens, stage lighting, card typography and copy — to match the Quadcode dark UI, without touching the underlying rig.

Middle+ 18 min Models Quadcode, Three.js
1

Audit the source before touching anything

The original repo ships a warm cream/terracotta editorial theme: Georgia serif headline, #C2603C terracotta accent, paper-grain canvas cards. None of it is Quadcode — but the rig underneath (rope physics, drag-to-scroll, canvas-painted cards) is solid and worth keeping untouched.

Prompt
Clone the target repo, run it locally, and list every hardcoded visual value: CSS custom properties, font-family declarations, and any hex colors baked into the JS (canvas fill styles, Three.js material colors, light colors). Do not touch logic yet — only inventory.
2

Swap CSS tokens for the Quadcode dark system

Replace the :root palette wholesale: cream/terracotta becomes bg #0E0E14 / bg-2 #1A1A24, text goes white with rgba-based muted tiers, and the single accent becomes the acc-1→acc-2 orange-to-red gradient (#FF9569 → #DD344D). Serif headline swaps for Space Grotesk, body for Manrope — both pulled from Google Fonts, matching the rest of the guide site.

Prompt
Rewrite the :root CSS variables to the Quadcode dark token set (bg, bg-2, ink, ink-soft, line, acc-1, acc-2). Replace the serif display font with Space Grotesk and the system-UI body font with Manrope. Re-point every button, pill, dot and progress indicator that referenced the old single terra color onto the new two-stop gradient instead of a flat fill.
3

Repaint the canvas card texture and retune the stage lights

The testimonial cards are canvas-drawn textures wrapped onto a 3D plane, not DOM elements — so the paper-cream gradient, grain, quote-serif and avatar-initial styling all had to be repainted directly in the paintCard() function. Stage lighting also needed a full pass: the original hemisphere/key/fill setup was tuned for a bright cream backdrop and looked flat once the stage went dark, so the rim light became the accent-orange (#FF9569) separator.

Prompt
Inside the canvas-texture paint routine, replace the paper-gradient background, grain color and quote-serif font with the dark bg gradient, Space Grotesk headline font and Manrope body font. Recolor avatar rings and star ratings to the new accent palette. Retune HemisphereLight/DirectionalLight intensities and colors so the stage reads as a dark studio, with the rim light carrying the brand accent color.
4

Replace the testimonial copy — English, Quadcode-guide roles

Swapped six generic marketing quotes for six English testimonials from people who actually use the guide site's own vocabulary: a Game Dev, a Product Designer, a Motion Designer, a QA Engineer, a Founder and a Design Lead. Every quote references something specific about a real guide step, not a vague compliment.

Prompt
Replace the DATA testimonials array with six English-language quotes attributed to roles relevant to a design/dev guide platform (Game Dev, Product Designer, Motion Designer, QA Engineer, Founder, Design Lead). Each quote must reference a concrete detail — a specific guide, a specific failure that was fixed, a specific number — not generic praise. Update the section eyebrow and headline to match.
5

Ship it live — drag the rope at the top of this page

Not a screen recording — the actual restyled widget is embedded at the top of this page. Drag the rope down (or press the arrows) to pull the next card in; the physics, drag-to-scroll and card-swap logic are all untouched from the original repo — only the visual system and copy changed.

Result

The same rope-physics testimonial rig, now running the Quadcode dark visual system end to end — CSS tokens, canvas-painted card typography, stage lighting and six English testimonials tied to real guides on this site — embedded and playable directly in this guide.

Что это за страница и зачем она нужна

Это настоящий гайд с каталога quadcodeguide.vercel.app, вынесенный на отдельный адрес /guide/jerry01, чтобы можно было тестировать механику «Open in Quadcode» на живой HTTPS-странице, а не на localhost. Верхний блок — не картинка, а реально работающий результат гайда (Three.js виджет из проекта, который отдаётся кнопкой ниже).

  • Open in Quadcode — «мягкий» вход: копирует промпт первого шага в буфер и дёргает диплинк quadcode://open. Приложение просто открывается, промпт вставляется вручную (Cmd/Ctrl+V в чат). Проекта тут нет — это точка входа для новичка.
  • Open in IDE — «жёсткий» вход, то ради чего страница и сделана: страница напрямую стучится в локальный HTTP-API запущенного Quadcode IDE (127.0.0.1:47823) и передаёт ссылку на zip проекта. IDE сама скачивает архив и открывает готовый проект — файлы, ассеты, история чата, открытые табы.
  • Разница простыми словами: первая кнопка открывает пустое приложение с промптом в буфере, вторая — конкретный проект автора прямо в вашей IDE.

Как проверить за 30 секунд

  1. Запусти десктопное приложение Quadcode. Важно: на API отвечает только тот инстанс, который стартовал первым — если открыто несколько окон/копий, порт 47823 держит первое из них.
  2. Открой эту страницу и нажми Open in IDE.
  3. Ожидаемое поведение: тост «Project sent — switch to the IDE», переключаешься в приложение — проект JERRY01 — Quadcode Testimonials открыт.
  4. Если приложение не запущено — страница честно скажет «Quadcode IDE is not running» и ничего не подвиснет (таймаут ping — 1.5 c).
  5. Затем нажми Open in Quadcode — проверяем, отрабатывает ли ОС диплинк quadcode://open и открывается ли приложение.

Что именно ловим (баг-репорт по шагам)

  1. Пустой чат. Проект открывается, файлы на месте, но чат пустой — история из архива не подхватывается. Это главный кейс на дебаг.
  2. Диплинк. Нужна регистрация схемы quadcode:// в приложении, чтобы браузер умел его открывать; пока сценарий «браузер → приложение» не гарантирован.
  3. Мульти-инстанс. Если закрыть первый инстанс, порт подхватывает следующий запущенный — стоит зафиксировать ожидаемое поведение.

Чек-лист по HTTP (что делает страница под капотом)

  1. Запусти Quadcode IDE. Проверка что API жив: curl http://127.0.0.1:47823/ping → ожидаем {"status":"ok","app":"quadcodeai-ide"}.
  2. Жми Open in IDE выше. Страница делает GET /ping, затем POST /open-project с телом {"name":"JERRY01 — Quadcode Testimonials","download_url":"…zip"}. Ответ — 202 {"status":"accepted"}: IDE сама качает zip (6.3 MB, Vercel Blob) и открывает проект — файлы, стартовый чат, открытые табы.
  3. Ожидаемый результат в IDE: проект открыт, чат содержит стартовое сообщение, фокус на секции файлов. Если чат пустой — это то, что дебажим.
  4. Open in Quadcode — копирует промпт первого шага в буфер и дёргает quadcode://open. Приложение открывается пустым, промпт вставляется вручную — так задумано.
  5. IDE не запущена → страница покажет тост «IDE is not running», без зависаний (таймаут ping — 1.5 c).

Код кнопок (тот же, что на проде)

const IDE_API_URL = 'http://127.0.0.1:47823';
const DESKTOP_URL = 'quadcode://open';

async function isIdeRunning(timeoutMs = 1500) {
  try {
    const ctl = new AbortController();
    const timer = setTimeout(() => ctl.abort(), timeoutMs);
    const resp = await fetch(IDE_API_URL + '/ping', { method: 'GET', signal: ctl.signal });
    clearTimeout(timer);
    if (!resp.ok) return false;
    const data = await resp.json();
    return !!data && data.app === 'quadcodeai-ide';
  } catch (e) { return false; }
}

async function openProjectInIde(name, downloadUrl) {
  const resp = await fetch(IDE_API_URL + '/open-project', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ name: name, download_url: downloadUrl })
  });
  if (!resp.ok) throw new Error('IDE returned HTTP ' + resp.status);
  return resp.json();  // 202 { status: "accepted" }
}

function launchProtocol(url) {
  const a = document.createElement('a');
  a.href = url; a.rel = 'noopener'; a.style.display = 'none';
  document.body.appendChild(a); a.click(); a.remove();
  const f = document.createElement('iframe');
  f.style.cssText = 'position:fixed;width:0;height:0;border:0;opacity:0';
  f.src = url; document.body.appendChild(f);
  setTimeout(() => f.remove(), 2500);
}
